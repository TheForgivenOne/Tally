# Surface brief: Tally shopping app (apps/web)

Scope: all six screens + shared components. Mode: Operate. Build path: code-led (app screens; no image generation in this harness).

Audience, job, action: Jamaican shoppers mid-trip, one-handed, bright aisles. Job: know the running total vs budget. Action per screen: pick store, set budget, capture prices, adjust basket, end trip.

Constraints: sunlight legibility (contrast first), touch targets ≥44px, low-end phones (no heavy effects), offline states, honest error copy. No behavior or copy-claim changes in this round — reskin only.

## Direction contract

THESIS: The app reads as a trustworthy market tool, not a tech demo: one green, ink text, tabular numerals, generous touch targets. It refuses the generic AI look (purple gradients, hero scaffolds, stock cards).

OWN-WORLD: paper-white wash ground, white surface cards with hairline borders, Tally green reserved for primary actions + budget health, amber/red only as warning fills; system type stack with tabular numerals for every price; 8px radius; icons as authored SVG strokes.

STORY: A shopper understands within seconds: where they are in the trip, the predicted total range, and whether the budget holds. Capture is one big thumb target; the basket is a scannable ledger.

FIRST VIEWPORT: Shopping screen — live viewfinder filling the upper half with mascot badge, pinned predicted-total card with budget bar directly beneath, single Capture price primary button thumb-wide, basket link secondary. No hero, no kicker, no intro text.

FORM: Committed Operate ledger; follows the approved V1 plan (user-pinned direction, no roll). Seed key: n/a (pinned brief).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
